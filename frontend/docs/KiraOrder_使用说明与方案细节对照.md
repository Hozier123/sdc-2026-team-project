对照日期：2026-10-22

## 1. 结论与核对范围

使用说明覆盖了“录入 → 核对 → 人工批准 → DO → 操作留痕”的主要路径。初稿仍有数量口径不准确、审批触发条件不完整、条件记录步骤不明确等问题；本次已完成 **12 类说明修订**。

**修订说明不等于补齐产品。** 首次对照列出 **10 组实现、接口或联调差异**。后续已在本地完成 G01 隐私页、G02 自动预热、G03 正式鉴权提示，并补上生成类型、fixture API 及字段适配；详见 [本轮开发与验收结果](前端独立开发与验收_2026-10-22.md)。G04～G10 仍需按范围或依赖推进，真实后端与 AI 未完成联调。

## 2. 主流程逐项对照

| 主题 | 方案 / 契约要求 | 当前实现与说明结论 |
| --- | --- | --- |
| 起始页进入 | v2.1 聚焦工作流，未规定现有 3D 入场方式 | 按用户后续明确要求，点击任意位置进入，支持 Enter / 空格；属于已接受的界面调整 |
| Trigger | P0 粘贴文本并选择客户；模拟入站属 P1 | 当前为手动输入；说明已明确未连接 WhatsApp，不把收件箱等同自动入站 |

| Decision Logic | 客户、老板、系统、跟单员四类分流 | 说明补充四类职责及 AI 边界，不能把所有疑点都称为老板审批 |
| Human Approval | 跟单员常规批准；三类例外由老板批准 | 已补齐具体升级规则、老板自批及任何人不可绕过的硬规则 |
| Visible Outcome | DO、批准扣库存、回复草稿、活动与差异记录 | 本地演示可展示；说明区分“送审”和“出单”，不把仓库勾选当作发货或扣库存 |
| 保存与重算 | 先保存，再批准已保存版本 | 说明保留 Save changes，并补齐 Record decision → Save changes 的顺序 |
| 人工记忆 | 经人工确认的客户级映射；不训练模型 | 当前保存操作写入客户级别名；说明补充保存时机及不能靠取消勾选撤销旧记忆 |

## 5. 需要保留的版本区别

1. **规则与持久化位置**：真实模式由后端计算金额、判升级、扣库存及裁剪权限；本地 `DemoService` 只是隔离的演示规则服务。不能用演示跑通证明后端事务正确。
2. **别名保存时机**：v2.1 §4.13 描述批准事务中保存勾选别名；Gate 0 `WorkingLineInput` 规定保存成功后返回 saved_alias，当前实现也是保存时写入。使用说明按当前契约说明；如团队要恢复“仅批准时生效”，应另行调整契约与实现。
3. **老板库存变化恢复**：v2.1 §5.2 倾向驳回后重新解析；Gate 0 `STOCK_CHANGED` 约定审批保持 PENDING、刷新后可重试。说明采用刷新核对、满足可重试；需要改量才驳回另建，兼容锁定版本的要求。
4. **DO 与仓库列表**：原方案列出 P1 DO 列表接口，但当前 Gate 0 只给详情和仓库按号读取。现有送货单索引依赖草稿摘要，不宜写成已具备独立后台全量 DO 列表。
5. **数量**：本版只支持整数目录数量。价格可以有小数，不代表商品数量也支持小数；无法安全解析的小数数量应转人工确认。
6. **授权与页面风格**：主页拆为 Overview / New order 等页面，以及全屏点击进入，属于当前已接受的界面组织；不因布局不同就判定业务规则不一致。

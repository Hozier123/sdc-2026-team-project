# KiraOrder 使用说明

适用版本：2026 年 10 月 22 日本地前端版  
适用人员：跟单员、老板、仓库人员及演示操作人员

本说明已对照终版执行方案 v2.1 与 Gate 0 前端契约修订，按当前本地版本的实际操作编写。方案要求与当前实现之间的差异见 [使用说明与方案细节对照](KiraOrder_使用说明与方案细节对照.md)。该对照不代表真实后端或真实 AI 已验收。

KiraOrder 用于将客户订货消息整理为订单草稿，经人工核对和批准后生成送货单（Delivery Order，简称 DO）。本文保留界面中的英文按钮名，便于对照操作。

**日常流程：录入消息 → 核对商品与条件 → 保存 → 批准或送老板审批 → 生成送货单 → 仓库拣货。**

处理原则：意思不清楚时由跟单员向客户确认；库存等数据问题由系统核对；价格、大额及账期提醒交老板决定；没有疑点的常规单由跟单员批准。AI 只辅助读取消息，不决定价格、库存或审批结果。

## 1. 启动与进入

在项目文件夹中双击 **启动 KiraOrder.command**。首次使用需要安装 Node.js 22 和 npm，启动脚本会在缺少依赖时安装依赖。

也可以在项目目录的终端中运行：

```sh
npm ci
npm run dev
```

启动后，浏览器打开终端显示的本地地址，默认是 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)。使用期间保持启动终端运行。

- 起始页：点击屏幕任意位置进入工作台；手机上轻触即可。
- 键盘：按 **Enter** 或 **空格**进入。
- 浏览介绍：滚动鼠标或上下滑动；滚动和拖动不会触发进入。
- 直接进入工作台：[http://127.0.0.1:5173/#/workspace](http://127.0.0.1:5173/#/workspace)。

## 2. 先认识工作台

左侧边栏是主要入口。手机上先点击左上角菜单图标展开边栏。

| 界面入口 | 用途 |
| --- | --- |
| **Overview** | 查看订单状态计数、待处理队列、推荐处理的订单和近期活动 |
| **New order** | 录入客户消息，创建订单草稿 |
| **Order inbox** | 按状态筛选、搜索并继续处理订单 |
| **Owner approvals** | 老板查看本租户审批并作决定；跟单员只读查看本人提交的审批 |
| **Delivery orders** | 查找已生成的送货单，打印、复制回复或查看审计记录 |
| **Activity log** | 查看和搜索操作记录 |
| **Connect API / API connection** | 连接真实后端，或查看并切换当前连接 |
| **Roles & permissions** | 查看当前身份与权限说明 |
| **Privacy & data** | 查看数据用途、脱敏、角色可见范围、存储及第三方处理说明 |
| **About KiraOrder** | 返回起始介绍页 |

仓库角色的业务入口为 **Warehouse**，显示经过裁剪的拣货页面。具体可用操作以当前身份及页面实际显示为准。

本地演示可切换 **Bintang Wholesale**（食品批发）与 **Bina Hardware**（五金）两个虚构工作区；应先保存当前修改再切换。真实 API 模式的身份与工作区由会话决定，不能用演示选择器改变真实权限。

## 3. 第一次使用：完成一笔演示订单

默认进入 **LOCAL DEMO** 本地演示模式，无需配置 API。

1. 在左侧工作区选择器选择 **Bintang Wholesale**。
2. 在右上角 **Demo role** 选择 **Order clerk · demo**。
3. 点击 **New order**，在 **Customer** 中选择一个客户。
4. 在 **Customer’s message** 输入以下演示消息，也可使用页面上的 **The everyday order** 示例：

   ```text
   Tepung 4 ctn
   Minyak 2 ctn
   ```

5. 点击 **Create order draft**。
6. 在核对页面检查商品、规格、数量、单位、单价、库存和合计。如有待处理疑点，按页面提示完成确认。
7. 如做了修改，点击 **Save changes**；保存后重新检查金额和状态。
8. 页面允许直接批准时，点击 **Approve & generate DO**；若显示 **Send to owner**，则按第 5 节完成老板审批。
9. 进入送货单页面后，记录 DO 号码，可打印单据或复制客户回复。

演示模式使用本地目录规则匹配，不调用真实 AI。出现 **Offline match · non-AI** 或类似提示属于此模式的正常表现；不熟悉的说法可能需要人工确认。

## 4. 跟单员：核对与修改订单

### 4.1 创建草稿

选择客户后，粘贴客户原始订货消息。尽量保留商品名称、规格、数量、单位和客户提出的价格或交付条件。

**Message language** 可选择自动识别、English、Bahasa Melayu 或中文。界面限制消息长度为 4,000；常用中英马来文字可按此上限录入。包含 emoji 等字符时，浏览器长度计数可能先达到上限。点击 **Create order draft** 后进入核对页面。

当前版本通过手动录入消息创建订单；复制 WhatsApp 消息到这里，不会自动收取 WhatsApp 消息。

### 4.2 核对商品

逐行确认以下信息：

| 核对项 | 操作要点 |
| --- | --- |
| 商品及规格 | 对照原消息，必要时从候选商品中重新选择 |
| 数量与单位 | 确认数字和目录单位；当前确认数量为 **1～100,000 的整数**，不支持 1.5 等小数数量 |
| 库存 | 查看是否满足需求；不能通过批准跳过库存限制 |
| 单价与金额 | 核对客户等级价格；人工改价时填写原因 |
| 客户条件 | 逐条确认价格、交付等条件及其适用商品 |

完成编辑后点击 **Save changes**。尚未保存时，页面金额可能仍是已保存版本的金额，应在保存后再次核对。

**Reset edits** 可撤销本轮未保存的编辑，恢复到当前已加载的保存版本。

确认数量留空时沿用解析出的请求数量；明确改量时输入合法整数。需要删除商品行时，使用该行删除图标，随后保存；不要把数量改为 0 表示删除。**Undo removals** 可撤销本轮待保存的删行；订单至少保留一行。

“kalau ada / 有货的话”由系统查库存，不需要人工点通过。有货条件记录本身不造成第二重阻断；缺货时按对应商品行提示减量或删除。保存后系统重新核对：减量可能关闭缺货疑点，加量或库存变化也可能重新打开。批准时还会再次检查库存，老板同样不能越过这条限制。

### 4.3 处理不清楚的说法

若商品或条件不明确：

1. 查看疑点和客户原文。
2. 点击 **Copy clarification** 复制澄清文案。
3. 自行通过原沟通渠道向客户确认。
4. 收到确认后，回到订单选择正确商品或处理方式，填写必要说明并保存。

人工选定商品并确认说法后，可勾选 **Remember this phrase for …**，再点击 **Save changes** 保存到当前客户范围。下次同一客户出现该说法时可得到匹配建议，仍需人工核对和批准。这里保存的是规则映射，不是训练 AI。

取消下一次保存时的勾选，不会撤销已经保存的记忆。当前界面没有别名撤销或租户级记忆管理入口。

### 4.4 处理客户议价

客户原文中的报价不会自动变成成交价。在 **Customer conditions** 中，根据实际沟通结果选择：

- **Customer agrees to tier price**：客户接受目录中的等级价格。
- **Accept a requested discount**：申请按议定价格成交，选择适用商品，输入单价及说明，交由老板决定。
- **This isn’t a condition**：判断该语句不是订单条件，并填写理由。

价格必须是**按目录单位计算的单价**，不能把“整单共 RM95”直接填成每件或每箱 RM95。若客户没有说清单价、总价或适用商品，先向客户确认。多个目标商品都必须明确适用价格及原因，不能用另一件商品的降价代替当前商品的价格确认。

填写后，先点击条件面板的 **Record decision**（已有记录时为 **Update decision**），再点击订单底部 **Save changes**。只填写备注而未记录决定，不会将该处理加入待保存内容。最终是否需要审批，以保存后显示的操作为准。

### 4.5 批准或送审

- **Approve & generate DO**：当前订单允许直接批准，批准成功后生成送货单。
- **Send to owner**：当前订单需要老板决定，提交后进入等待审批状态。

按钮不可用时，先检查未保存编辑、未解决疑点、库存限制及当前角色权限。页面正在保存或提交时，等待操作完成后继续。

演示规则中，下列任一情况需要老板审批：

| 触发原因 | 规则 |
| --- | --- |
| 低于等级价 | 成交单价低于该客户的等级价，包括接受客户折扣 |
| 大额订单 | 订单总额**达到或超过**租户阈值：食品批发 T1 为 RM 1,500，五金 T2 为 RM 800 |
| 账期提醒 | 客户主档带有账期提醒标记 |

账期提醒是演示中的合成标记，不会计算真实账龄或冻结客户。真实 API 模式以服务端的租户配置、返回原因和可用动作为准；即使价格未变，也可能因金额或客户提醒而送审。

老板本人在核对页面批准命中升级规则的订单时，可直接生成 DO，并记录 **OWNER_SELF_APPROVED** 自批路径和原因，不必再提交给自己。未解决的阻断疑点及库存不足仍不能放行。

## 5. 老板：处理审批

本地演示可通过 **Demo role → Owner · demo** 切换为老板。真实 API 模式的身份由登录会话决定。

1. 打开 **Owner approvals**，选择待审批请求。
2. 核对请求快照中的客户消息、商品、价格、金额、升级原因、字段修改及库存检查结果。
3. 同意时点击 **Approve & generate DO**。批准成功后生成送货单。
4. 不同意时点击 **Reject with reason**，填写理由，再点击 **Reject order**。

审批针对提交时的已保存版本。**等待老板审批、已生成 DO、已关闭的订单均不能继续修改明细。** 已批准或已驳回的请求会显示决定记录；驳回是终态，需要重新下单时重新解析原消息并创建新草稿。

老板批准时如出现 **STOCK_CHANGED**，先使用错误区域的刷新入口核对库存；库存恢复且满足时可重试。若需改量，老板应填写理由驳回，跟单员另建草稿，不能在等待审批的旧版本中直接改量。

本地演示中，具备权限的跟单员或老板可在尚未送审的可编辑草稿底部点击删除图标关闭整张草稿，并填写原因。关闭会保留历史。当前真实 API 契约没有草稿作废端点，真实连接模式不提供这个演示操作。

## 6. 送货单、客户回复与操作记录

在 **Delivery orders** 中按客户名称或 DO 号码搜索，点击记录打开详情。

- **Print / save as PDF**：打开浏览器打印窗口。选择打印机打印，或使用浏览器提供的“另存为 PDF”。
- **Copy customer reply**：复制客户回复草稿；检查内容后自行粘贴到沟通渠道发送。
- **View change record**：查看初始信息、最终结果、字段修改和时间线。
- **Activity log**：从全局查看并搜索订单相关操作记录。

送货单是已批准的只读记录。复制澄清或回复文案只会复制到剪贴板，不会自动向客户发送消息。

批准成功后，本地演示服务扣减演示库存，并生成 DO、回复草稿及活动记录；真实模式应由后端在批准事务中执行这些操作，当前尚未完成真实联调。送审只是创建待办，不等于已出单或已扣库存。仓库勾选不会再次扣减。

若重复点击批准后收到 **ALREADY_APPROVED** 且返回已有 DO 号码，前端会打开已有送货单；先核对结果，不要因此再新建相同订单。当前送货单不提供批准后改单流程。

## 7. 仓库：查找与核对拣货单

1. 本地演示切换 **Demo role → Warehouse · demo**。
2. 在 **Delivery order number** 输入已批准的 DO 号码。
3. 点击 **Find picking list**。
4. 对照商品、数量、单位和拣货要求准备货物，可逐项勾选核对。
5. 需要纸质清单时点击 **Print picking list**。

在 **Bintang Wholesale** 演示工作区可使用初始号码 `DO-T1-0001`，也可使用刚生成的送货单号码。

仓库页面不显示价格和联系人信息。同一商品、单位及拣货要求相同的条目会合并数量；要求不同的条目分开显示。

**勾选框仅是当前页面的临时核对清单，不会提交发货、扣减库存或持久保存拣货进度；刷新或重新查询后需重新核对。**

## 8. 识别订单状态

| 状态标签 | 含义与下一步 |
| --- | --- |
| **Needs your decision** | 存在需要核对或处理的疑点，打开订单完成确认 |
| **Ready to approve** | 可继续执行批准流程，先检查保存结果及可用按钮 |
| **With owner** | 已送老板审批，在审批列表查看进展 |
| **DO generated** | 送货单已生成，可打印、回复客户及安排拣货 |
| **Closed** | 草稿已关闭或请求被驳回，查看原因；继续下单需新建草稿 |

可在 **Order inbox** 使用状态筛选和搜索缩小范围。

## 9. 连接真实 API

本节适用于已取得后端 API 地址和会话令牌的人员。当前交付版已完成本地演示及模拟接口验证，真实后端和真实 AI 仍需联调。

1. 保存当前编辑，或使用 **Reset edits** 撤销未保存编辑。
2. 点击侧栏 **Connect API**。
3. 在 **API base URL** 填写完整接口地址，例如 `http://127.0.0.1:8000/api/v1`。
4. 在 **Session token** 填写会话令牌。
5. 点击弹窗中的 **Connect API**。
6. 连接成功后，按后端返回的用户、工作区和权限开展操作。

连接后，录入的订单消息会提交给所连接的后端进行处理。请核对接口地址，并勿在截图或分享材料中包含会话令牌。

令牌只保存在当前页面内存中；**刷新页面后回到本地演示模式，需要重新连接 API**。连接期间可打开 **API connection**，点击 **Return to demo** 返回演示。

如连接失败，核对地址、令牌和后端是否启动。远程接口使用 HTTPS；本机开发地址可用 HTTP。后端需允许此前端地址的跨域访问（CORS）。

顶栏 AI 状态包括就绪、预热中、离线及降级。跟单员与老板可点击 AI 状态按钮请求唤醒；状态读取失败时，该按钮显示 **AI unavailable · Retry**，点击重试读取。仓库没有唤醒权限。本地演示始终明确显示 **Offline match · non-AI**，唤醒不会让本地规则变成真实 AI。

当前没有独立的 **Wake AI** 文字按钮，手动入口为顶栏状态按钮。有唤醒权限的已连接会话首次进入业务页时会自动预热一次；页面间切换不会重复发起。本地演示、仓库身份和起始介绍页不自动唤醒。唤醒不等于创建或批准订单；失败后可通过状态按钮重试。

如果真实后端尚未就绪，可使用本机 fixture API 核对页面：开发人员运行 **npm run mock:api**，在连接框使用地址 `http://127.0.0.1:4191/api/v1`，分别以 `fixture-clerk` / `fixture-owner` / `fixture-warehouse` 作为合成测试标识连接。页面显示 **FIXTURE MOCK**。这套服务只返回预设快照，不处理任意真实订单、不启动 AI 或实际库存事务；场景切换方法见 [前端独立开发与验收](前端独立开发与验收_2026-10-22.md)。

## 10. 常见情况与处理

| 遇到的情况 | 建议操作 |
| --- | --- |
| 找不到某个入口 | 展开侧栏；核对当前角色。仓库身份只提供仓库业务视图 |
| 创建按钮不可用 | 选择客户、输入非空消息，并等待客户列表加载完成 |
| 批准按钮不可用 | 先保存修改，处理阻断疑点，核对库存及权限 |
| 发现改错了，尚未保存 | 点击 **Reset edits** 恢复本轮编辑 |
| 出现版本冲突 | **Cancel** 返回；**Keep edits & load latest** 保留可合并编辑并加载最新版，随后重新核对和保存；**Discard edits & reload** 放弃未保存编辑并加载最新版 |
| 保留编辑失败 | 按弹窗说明处理；若订单已锁定或被编辑行已删除，可取消检查，或放弃编辑后加载最新版 |
| 可编辑草稿库存不足 | 核对最新库存，在对应行减量或删除，保存后重新检查 |
| 等待审批时库存变化 | 刷新核对；库存满足可重试批准。需改量时先驳回，再另建草稿 |
| 某块内容加载失败 | 使用该区域提供的重试入口；其他已正常加载的内容可继续查看 |
| 会话过期 | 打开 **Connect API / API connection**，使用有效令牌重新连接 |
| 提示没有权限 | 查看 **Roles & permissions**；真实 API 模式下联系工作区负责人核对账号权限 |
| 复制未成功 | 选中文案后手动复制 |
| 仓库查不到单据 | 核对 DO 号码、当前工作区和批准状态；未批准草稿没有可用的拣货单 |
| 价格配置缺失（MISSING_TIER_PRICE） | 请管理员补齐客户等级与商品的价格配置；不能靠随意填价格绕过 |
| 请求过于频繁（RATE_LIMITED） | 按服务端提示稍后重试，勿连续点击解析或唤醒 |
| AI 与兜底均不可用 | 保留输入，待服务恢复后重试；此时不能假设已创建安全草稿 |
| 离线时起始页背景缺失 | 当前 3D 起始页的视频和封面依赖网络；可使用直接工作台地址进入本地演示 |

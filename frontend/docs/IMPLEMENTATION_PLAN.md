# KiraOrder 前端分步执行方案

日期：2026-10-22。交付范围为本地前端工程，不发布、不发送材料、不修改确认包。

本文保留首轮实施方案和历史调整。当前入口已采用 3D `PlanetGreeting`，原 70% 页面作为兼容入口；当前运行说明以 README 为准。审核清单修复及验证见 [逐项修复结果](审核问题修复结果_2026-10-22.md)。

## 依据与取舍

- 业务依据：终版执行方案 v2.1，数据形状、权限与状态以 Gate 0 v2.3 确认包 contracts 为准。
- 视觉依据：用户指定的 KiraOrder.html，保留原始星空、语言轨道、球体与滚动叙事。仅接入入口跳转并增加可随时进入的快捷入口。
- 材料内的部署、签字、发送、冻结等内容仅为背景，不视为本次操作授权。
- 未安装 frontend-design、vercel-react-best-practices、ui-ux-pro-max；不依赖它们阻塞开发。

## 1. 起始页

原星空 HTML 保留于 public/intro-scene.html，由 public/intro.html 以 70% 等效浏览器缩放加载。同源 iframe 与主应用通过严格校验的 postMessage 连接；点击原进入按钮或顶部快捷入口后进入 #/workspace。进入后卸载动画，避免占用后台帧。

## 2. 主页

左侧为固定工作区导航，顶部为租户、解析状态和角色。主区包括问候语、关键队列数量、一条主操作“New order”、待处理订单表；右侧为“下一步”工作建议与活动摘要。使用深蓝黑底、薄荷绿操作色、冰蓝辅助色，标题采用原页衬线气质，操作正文使用清晰无衬线。数字全部源自当前演示记录，不展示虚构的效率指标。

## 3. 订单工作台

新建：选客户、粘贴混语消息、解析。核对：原文与商品并排；商品规格、数量、库存、等级价可见。疑点写清原话、原因、责任方、可采取的动作。澄清和回复只复制、不自动发送。保存后方可批准；未解决阻断疑点、缺货、未保存修改阻止批准。

## 4. 审批与交付

跟单员正常单直接出单；降价、金额阈值、账期提醒走老板。老板看到绑定版本、升级原因、库存与变更；驳回必须备注。生成送货单后可查看、打印、复制回复、查看活动与差异。仓库使用单独裁剪后的数据投影。

## 5. 数据边界

默认可恢复的本地演示模式，所有种子为合成业务样例。输入先在本地掩码手机号、邮箱和证件号，再存储。离线解析明确标记 Offline match · non-AI，不冒充模型输出。演示领域逻辑独立于 UI；真实 API 适配器不在前端计算金额或判断权限，动作由 allowed_actions 决定。真实连接凭证只在内存中，不写磁盘。

## 6. 验证与交付

执行 TypeScript 与生产构建；领域回归涵盖缺货减量/恢复、议价范围、权限、版本冲突、重复批准和脱敏；浏览器验证原入口跳转、常规单、疑点解决、老板批准与驳回、仓库裁剪、页面刷新、手机布局。交付源码、启动说明、截图与验证记录。

## 1. 前端与用户操作

### 页面、视觉和导航

- 首页从原有介绍升级为 GSAP 三层纵深与原生滚动叙事：星云、语言字段和文字平面各自移动，段落按滚动阈值切换；停止滚动时文字仍能完整显现。收尾入口、键盘进入、隐藏页面暂停及 WebGL 失败后的工作台入口均得到处理（`7e71044`、`aee285f`、`2e1dfc8`）。
- 深浅主题切换采用从开关位置扩散的径向过渡；介绍页、工作台概览、菜单和弹窗保留各自的短动效。已取消的新增“整页路由切换动效”不在当前代码中（`2e1dfc8`、`ca9bac0`；[设计记录](../frontend/DESIGN.md)）。
- 工作台重新安排统计、下一任务、订单队列和手机阅读顺序；状态词、保存/审批动作、阻断检查及空态信息更明确。表单选择器统一键盘操作、输入匹配、触控尺寸和窄屏布局（`0da4d5e`、`2e1dfc8`）。
- 修正 GitHub Pages 子路径下的字体引用，分离首页 3D 资源与工作台加载；对手机导航抽屉、焦点管理和进入失败场景补强（`8716bd4`、`9628dd3`）。

### 订单、审批和配送

- 未提交草稿可作废；复制澄清问题会记录可追踪的复制事件，复制本身不表示消息已发送。同日订单提供独立新增、关联原配送单的追加及人工处理原单等明确路径（`0ff7f0e`、`004fec8`、`65ab0b1`）。
- 订单复核更突出商品规格、数量、单位、库存、等级价、小计和真正的阻断项；未选中商品的金额标为“已匹配小计”，价格请求、库存检查和其他待决事项使用不同说明。保存、重新核对和送审的顺序更清楚（`9628dd3`、`3fa2d88`、`ca9bac0`）。
- 审批列表与详情补充提交时间、草稿简号、版本和申请人信息；低价请求兼容新旧价格字段，缺失金额时不显示虚构的零元。审批通过或拒绝后可追看结果与相关活动；拒绝不会显示配送单或扣库结果（`f22569d`、`40e01a8`）。
- 配送单、仓库拣货和活动页完善关联跳转与按订单筛选。仓库界面只呈现允许的拣货字段，并对真实 API 意外返回的额外敏感字段采取拒绝显示的保护（`9628dd3`、`40e01a8`）。

### 连接、目录和人工恢复

- 1.5.0 起明确区分本地演示、固定夹具和真实 API；真实身份、租户与角色来自 `/me`。会话凭据只保留在当前内存；刷新后走明确的重新连接流程。订单提取标签使用该订单保存的实际 `ai_mode`，不拿当前模型就绪状态改写旧订单（`9628dd3`）。
- AI 处于预热中时，前端只轮询状态，不重复触发预热；连接失败、权限不足及请求编号得到可见提示（`f8ff1d7`、`9628dd3`）。
- 1.5.1 加入租户只读产品目录，展示规格、空目录、权限和目录截断状态；目录本身不显示价格或库存，也不把选中商品视为可批准订单（`befac4c`；[目录契约](ops/b02-catalog.md)）。
- 随后的真实 API 人工恢复允许从目录改选现有行、在零有效行时补录新行、删除并补正行；必须确认数量，先保存再重新核价、核库存和判断审批。超时、版本冲突和重复提交均有恢复路径；人工选择不会冒充 AI 识别（`6ba0d85`；[前后端调用顺序](ops/b03-manual-recovery.md)）。

### 1.5.2 的当前界面整理

- 当前屏幕呈现统一放大到 110%，打印文档保持原比例；亮暗主题的次要文字与占位文字提高对比度，关键状态数、客户信息和复核值加粗。规格与五类订单字段值此前已提升到 18px、标签保留 14px（`3fa2d88`、`ca9bac0`）。
- 审批和配送列表悬停改为整行浅色反馈，内容位置不跳动；键盘焦点有独立轮廓。窄屏顶栏和侧栏提示调整，避免放大后横向溢出；检查栏文案区分价格请求、库存与未决事项（`ca9bac0`）。
- 前端版本显示、`package.json` 和锁文件根包版本现统一为 **1.5.2**。锁文件里第三方依赖自身的 `1.5.1` 版本保持不变。

## 2. 后端 API 与订单规则

- 在 1.4.0 已有的身份、解析、保存、审批及配送基础上，补齐草稿列表/详情、客户、活动、配送单审计详情、仓库专用读取，以及 AI 状态/预热接口；支持刷新恢复、追溯和服务端字段裁剪（`da75feb`；[后端审计](audit/backend-audit-2026-10-23.md)）。
- 新增租户商品解析与候选选择、客户级别名记忆及 `ALIAS_ONLY` 来源；补齐多语言澄清、确认回复、来源证据和逐行无效结果隔离。旧的 `confirmed_items` 兼容路径在同一事务中保存并批准（`ebe5c64`、`6eccb90`、`5bb6591`、`4604612`）。
- 同单并发批准、库存竞争、故障回滚和审计写入增加检查；可配置的 `checks_enabled` 软检查按租户生效，合同错误分支得到回归覆盖（`4c14012`、`64510b3`、`480486e`）。
- 草稿作废、澄清复制记录和同日订单处理与前端流程对应；产品导出证据绑定文件哈希，金额导出保留两位小数（`3431c62`、`495eeb8`、`61eedf0`、`bb1c941`、`8b298f2`）。
- 老板对已终结审批请求的重试现在返回准确的 `409 ALREADY_APPROVED` 或 `409 DRAFT_REJECTED`；真正仍待批的请求保留原有待批状态。锁、库存事务和已有审批结果不因此改变（`9dfee33`；[C07 记录](ops/c07-release.md)）。
- 增加只读 `GET /api/v1/catalog/products`：仅当前租户有效商品，店员/老板可读、仓库拒绝；单次最多 100 项并返回是否截断，不返回价格、库存或客户信息（`f767e7b`、`befac4c`）。
- 人工改选/补录在服务端记录 `MANUAL_SELECTED`，保留原始证据，要求合法数量与版本；删行、改 SKU 或改接受价后，原价格决定必须重新绑定与确认，批准时再次核库存和价格（`99ee169`；[B03 记录](ops/b03-manual-recovery.md)）。
- 对缺少单位的混合单位商品，解析、保存、批准三段均保持阻断；显式单位、包装规格和租户专属单位别名分别按语义处理，不能只选择 SKU 就绕过检查（`436eec6`；[D02 记录](audit/d02-uom-blocking-2026-10-31.md)）。
- 种子与重置入口新增原始字节预检；正式 `gate0/` 契约、`frontend/contracts/` 和种子 SQL 在本范围内未改动（`dfb586a`）。

## 3. AI 接入与就绪语义

- 新增进程内 RunPod 适配器、抽取提示、目录映射和本地回退；旧 HTTP 接口与租户目录路径分离。行外条件仍能保留，数量单位优先于包装规格单位；逗号小数、脱敏片段和缺单位的不安全 SKU 选择得到保护（`3f0bc27`、`93dcccd`、`40319f8`、`657ad5d`、`076ddf1`、`c93d6d0`）。
- Provider 配置统一为 `auto`、`stub`、`http`、`runpod_adapter` 的明确选择；解析和状态管理共用同一次启动配置。后台预热区分 OFFLINE、WARMING、DEGRADED、READY，READY 需要近期有效推理证据；预热受理不等于模型可用（`f8ff1d7`、`555f0fa`；[B01 记录](ops/b01-provider-readiness.md)）。
- 六样例运行、真实/模拟调用的脱敏证据及模型就绪诊断工具被归档；运行依赖和测试依赖随之更新。评测记录与正式端到端验收分开解释（`1e814de`；[证据索引](../evidence/EVIDENCE_INDEX.md)）。
